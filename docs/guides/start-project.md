# Как повторно запустить весь проект «Рядом»

[Вернуться в README](../../README.md)

Инструкция для случая, когда проект уже один раз настроен: установлены Node.js, Python и зависимости, создан `backend/.env`, а таблицы БД подготовлены. Если запускаете проект впервые или скачали его на новый компьютер, сначала выполните установку из README.

Для полной работы нужно запустить три части: PostgreSQL, сервер FastAPI и интерфейс React. Ниже используем Docker для PostgreSQL. Если вы установили PostgreSQL отдельно, запустите его службу вместо Docker и используйте ранее настроенное подключение.

## Что открыть перед запуском

1. Запустите **Docker Desktop** и дождитесь, пока он будет готов. В Linux с Docker Engine достаточно работающей службы Docker.
2. Откройте папку проекта в **VS Code**.
3. Откройте терминал через **Терминал → Создать терминал**.

**Корень проекта** — папка, в которой находятся `package.json`, `compose.yaml`, `README.md` и папка `backend`. Это не папка `docs/guides`, где лежит эта инструкция. Если терминал открыт в другом месте, перейдите в папку проекта командой `cd`.

Например, для Windows:

```powershell
cd "C:\Projects\fullstack"
```

Замените пример пути своим. Далее понадобятся **два терминала**: один для backend, второй для frontend. База данных работает в фоне.

## Windows: терминал № 1 — база данных и backend

Находясь в корне проекта, выполните:

```powershell
docker compose up -d --wait db
```

Дождитесь завершения команды. Она запускает PostgreSQL в фоне и ждёт его готовности. Уже работающий контейнер просто останется запущенным. Проверить состояние можно командой:

```powershell
docker compose ps
```

У сервиса `db` должно быть состояние `healthy`. После этого в том же терминале:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Если терминал уже находится в `backend`, повторно выполнять `cd backend` не нужно. Но команды `docker compose` в этой инструкции выполняйте из корня проекта; вернуться из `backend` в корень можно через `cd ..`.

После запуска появится сообщение примерно такого вида:

```text
Uvicorn running on http://127.0.0.1:8000
Application startup complete.
```

**Оставьте этот терминал открытым.** Он занят работающим сервером — это нормально. Для следующего шага создайте второй терминал кнопкой `+` на панели терминала VS Code.

### Что означает команда с uvicorn

`Uvicorn` — название сервера, который запускает наше приложение FastAPI.

| Часть команды | Значение |
| --- | --- |
| `.\.venv\Scripts\python.exe` | Python из окружения проекта с установленными зависимостями |
| `-m uvicorn` | Запустить модуль сервера Uvicorn |
| `app.main:app` | Взять объект `app` из файла `backend/app/main.py` |
| `--reload` | Перезапускать сервер автоматически после изменения Python-кода |

Создавать окружение, устанавливать библиотеки и запускать `init_db` каждый раз не требуется.

## Windows: терминал № 2 — frontend

Убедитесь, что новый терминал находится **в корне проекта**, где лежит `package.json`. Если он открылся в `backend`, выполните `cd ..`.

Запустите:

```powershell
npm run dev
```

Терминал покажет адрес, обычно:

```text
Local: http://localhost:5173/
```

**Этот терминал тоже оставьте открытым.** Если PowerShell блокирует запуск `npm.ps1`, используйте:

```powershell
npm.cmd run dev
```

## macOS / Linux

В терминале № 1, из корня проекта:

```bash
docker compose up -d --wait db
cd backend
.venv/bin/python -m uvicorn app.main:app --reload
```

В терминале № 2, также из корня проекта:

```bash
npm run dev
```

Оба терминала остаются открытыми. Активация `.venv` отдельной командой не нужна: сервер запускается напрямую через Python из этого окружения.

## Какие адреса открыть и что проверить

| Адрес | Для чего нужен |
| --- | --- |
| http://localhost:5173 | Интерфейс «Рядом»: главная, история и формы |
| http://127.0.0.1:8000/docs | Swagger UI: проверка запросов к backend |

Для frontend используйте точный адрес из терминала: если 5173 занят, Vite может выбрать следующий порт. В Swagger для загрузки оформления и скриптов нужен интернет.

Проверьте запуск так:

1. Откройте интерфейс, перейдите в историю и добавьте измерение. Оно должно появиться в списке.
2. Откройте `/docs`, раскройте `GET /api/profiles`, нажмите **Try it out → Execute**. Ожидается ответ `200`; если профилей ещё нет, тело ответа будет `[]`.
3. Для проверки записи в БД выполните `POST /api/profiles` с телом `{"name": "Учебный профиль"}`. Полученный ID можно использовать при создании измерения, как показано в README.

**На этапе лабораторной № 3 frontend и backend ещё работают отдельно.** Даже при одновременном запуске всех частей интерфейс использует учебный JSON. Изменения через интерфейс исчезают после обновления страницы. Данные, созданные через Swagger, хранятся в PostgreSQL и сохраняются после перезапуска, но пока не отображаются в React.

## Как правильно остановить проект

1. В терминале frontend нажмите **Ctrl+C**.
2. В терминале backend нажмите **Ctrl+C**.
3. Когда в терминале backend снова появится строка для ввода, вернитесь в корень и остановите БД:

   ```bash
   cd ..
   docker compose stop db
   ```

Если уже находитесь в корне, выполняйте только `docker compose stop db`.

Данные БД сохраняются в Docker-томе. Для обычной остановки достаточно `stop db`. Команда `docker compose down -v` удаляет том с данными, поэтому её для остановки не используйте.

## Если не запускается

| Что происходит | Что проверить |
| --- | --- |
| Docker сообщает, что не может подключиться к daemon | Docker Desktop или служба Docker должны быть запущены |
| Не найден `compose.yaml` | Терминал должен находиться в корне проекта |
| npm не находит `package.json` | Перейдите в корень проекта |
| Не найден Python по пути `.venv` | Проверьте, что вы в `backend` и первое создание окружения уже выполнено |
| `ModuleNotFoundError: app` | Запускайте команду Uvicorn из папки `backend` |
| Ошибка подключения к PostgreSQL | Проверьте `docker compose ps` и параметры в `backend/.env` |
| Порт 8000 занят | Возможно, backend уже запущен в другом терминале; проверьте его и не запускайте вторую копию |
| Порт 5432 занят | Возможно, уже запущена другая PostgreSQL; используйте нужный экземпляр или настройте другой порт по гайду № 2 |
| На `http://127.0.0.1:8000/` ответ 404 | Для проверки API открывайте адрес с `/docs`; интерфейс находится на порту Vite |
| После закрытия терминала адрес перестал открываться | Запустите соответствующий сервер снова и оставьте терминал открытым |

Если после обновления проекта изменились зависимости, может понадобиться повторная установка из README. Для обычного повторного запуска той же версии достаточно команд выше.
